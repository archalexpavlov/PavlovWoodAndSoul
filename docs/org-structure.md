# Офис: вложенные проекты, свой git у каждого отдела

Проект от 1 ноября 2026, не реализован. Механика проверена по документации —
`docs/claude-setup.md`.

**Задача словами Алекса.** Офисное здание: генеральное управление, под ним маркетинг,
разработка и правовой отдел. Внутри маркетинга — своё управление и команды: сайт,
соцсети, партнёрка. У каждого этажа **своя ответственность, свои знания, свой roadmap,
свои вопросы и своё контекстное окно**. Каждый отдел — отдельный проект в Claude Code
со своим git, как плагин в проекте Unreal: чтобы запушить корень, сначала коммитишь
плагин. Генеральный принял решение и закоммитил — нижестоящие видят это хуком,
подтягивают изменения и обновляют свой контекст. Задача идёт вниз, но может быть
возвращена наверх, если нереализуема.

**Отдельные определения агентов не нужны: каждый проект и есть агент**, работающий
в границах своего репозитория.

Группируются в папку «Pavlov», как уже сгруппированы нынешние проекты.

# Что даётся механикой бесплатно — проверено

## Контекст сверху вниз, через границы репозиториев

Документация дословно: Claude Code грузит `CLAUDE.md` **из рабочей папки и каждой
папки выше**, содержимое выстраивается **от корня файловой системы вниз к рабочей
папке**. Про остановку на границе `.git` не сказано ничего — **подмодуль её не
останавливает**.

Сессия, запущенная в `marketing/site/`, получает при старте:

```
1  PavlovGeneral/CLAUDE.md      зачем компания существует
2  marketing/CLAUDE.md          зачем существует отдел
3  marketing/site/CLAUDE.md     что делает эта команда
```

**Именно в этом порядке, ближайшее читается последним.** Это и есть твой лифт,
и он уже работает — строить нечего.

## Указатель подмодуля = приёмка работы

Родительский репозиторий хранит, на каком коммите дочернего он стоит. Пока
генеральный не обновил указатель, компания официально стоит на прежней версии отдела.

**Обновление указателя — это и есть акт приёмки.** Не метафора: отдел закоммитил
и запушил у себя, генеральный посмотрел и сдвинул указатель. Механизм согласования
получается даром, из обычной работы git.

Отсюда же дисциплина из твоей аналогии с Unreal: **сначала коммит в отделе,
потом указатель в родителе.** У нас это уже так с `Site/`.

# Что не работает и чем лечится

## 1. Навыки не пересекают границу репозитория

Проектные skills поднимаются по дереву **только до корня репозитория**,
а подмодуль сам себе корень. Корневые навыки в отделах не появятся.

**Лечение: общие навыки кладутся в `~/.claude/skills/`** — пользовательский уровень
грузится в любом проекте, независимо от репозитория. Отдельские навыки остаются
в отделе.

Разделение выходит осмысленное: «как мы коммитим» — общее, пользовательское.
«Как собирается пост» — маркетинговое, живёт в маркетинге.

## 2. После компакта возвращается не весь лифт

Таблица выживания контекста обещает переинжекцию **корневого** `CLAUDE.md`
и загрузку вложенных **по требованию**. Как она считает «корневой» для сессии,
запущенной в `marketing/site/`, — из документации однозначно не следует.

**Не выясняем, а закрываем.** Строка `SessionStart` с матчером `compact` —
единственная в таблице, которая гарантированно возвращает что угодно: Claude Code
запускает хук и кладёт вывод в сжатый контекст.

Хук идёт от рабочей папки вверх до генерального уровня и отдаёт `CLAUDE.md`
и `STATE.md` каждого пройденного уровня. Тогда после обнуления агент в команде сайта
снова знает цель компании, цель отдела и свою задачу — независимо от того, как
Claude Code трактует слово «корневой».

## 3. Права задаются на каждом этаже отдельно

Общий `.claude/settings.json` читается **из рабочей папки сессии**, вверх по дереву
не идёт. Один корневой файл прав на все отделы не распространится — у каждого свой.

# Кто что пишет: правило, снимающее конфликты структурно

**Каждый уровень пишет только в своём репозитории. Никто не пишет в чужом.**

Связь идёт чтением, а не записью:

```
генеральный  пишет ORDERS.md у себя   →  отдел его читает (это папка выше)
отдел        пишет REPORT.md у себя   →  генеральный его читает (это папка ниже)
```

Два агента физически не могут взяться за один файл. Это надёжнее запрета, потому что
работает структурой, а не послушанием. Запреты ставятся сверху как подстраховка:

| Кто | Пишет | Читает | Запрещено |
|---|---|---|---|
| генеральный | свой репозиторий | все отделы | — |
| отдел | свой репозиторий | генеральный, свои команды | писать выше и вбок |
| команда | свой репозиторий | свой отдел, генеральный | писать выше и вбок |

Подстраховка — правила `permissions.deny` по путям в `.claude/settings.json` каждого
этажа. Синтаксис проверен: `Edit(путь)` покрывает любую запись в файл,
`Edit(**/имя/**)` ловит на любой глубине.

# Как ходят задачи и решения

## Вниз: смена курса

Генеральный правит `CLAUDE.md` или `ORDERS.md` и коммитит.

У каждого отдела в `.dev/` лежит отметка — хеш родительского коммита, который он уже
усвоил. Хук `SessionStart` сравнивает её с текущим состоянием родителя. Разошлись —
хук печатает список коммитов и дифф по `CLAUDE.md`, `ORDERS.md` и `ROADMAP.md`.

Агент отдела видит это первым делом, **обновляет свой `ROADMAP.md` и `QUESTIONS.md`**,
пишет в `REPORT.md`, что принял, и двигает отметку.

Ровно то, что ты описал: увидели коммит от генерального, подтянули изменённое,
обновили свой контекст. Реализация — несколько строк оболочки, не разработка.

## Вверх: возврат и отчёт

Отдел пишет в своём `REPORT.md` датированными записями трёх видов:

```
ПРИНЯТО     задача взята в работу
СДЕЛАНО     что получилось
ВОЗВРАЩЕНО  почему задача нереализуема или требует решения выше
```

Генеральный читает `REPORT.md` всех отделов. Возврат — это вопрос, который поднимается
на уровень, где есть право его решить.

## Утро генерального

Что сделано за вчера, одной командой по всем этажам сразу:

```
git submodule foreach --recursive "git log --oneline --since=yesterday"
```

Плюс свежие записи в `REPORT.md` каждого отдела. Это оформляется навыком `/статус`
на генеральном уровне и вызывается по имени — автоподхват для обязательного не годится.

# Честная цена

**Подмодули неудобны.** Оторванная голова по умолчанию, забыл запушить дочерний —
родительский указатель ссылается в никуда, клон требует `--recursive`. У тебя уже есть
один подмодуль, и в `CLAUDE.md` уже записан танец в два коммита. С пятью этажами
этого танца станет в пять раз больше.

**Альтернатива — один репозиторий с вложенными папками.** Тогда навыки наследуются
сами, никакого танца. Но пропадает ровно то, ради чего ты это затеял: свой git
у отдела, своя история, указатель как приёмка. Коммиты всех отделов смешиваются
в одну ленту.

**Рекомендация: подмодули, но строить по одному.** Сначала один этаж целиком, прожить
с ним неделю на живых задачах. Если танец с двумя коммитами окажется невыносимым,
откатиться к вложенным папкам можно; обратно — уже нет.

# Порядок работ

```
1  блок цели первым в генеральном CLAUDE.md — пятнадцать секунд чтения
2  хук идёт вверх по дереву и отдаёт контекст каждого уровня
3  первый этаж целиком: свой репозиторий, CLAUDE.md, ROADMAP, QUESTIONS, REPORT, права
4  хук сравнения с родителем и отметка усвоенного коммита
5  навык /статус на генеральном уровне
6  правило «пишем только у себя» в RULES.md
7  разделы боковой панели — когда этажей станет больше одного
```

Пункты 1 и 2 имеют смысл сами по себе, даже если этажей так и не появится:
без них после каждого компакта теряется то, ради чего всё затевается.

Что нужно от Алекса до начала: **какой этаж первый.**
