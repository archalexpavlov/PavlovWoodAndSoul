# Как организован проект в Claude Code

Собрано 1 ноября 2026. Отвечает на раздел «Организация работы» в `QUESTIONS.md`.

Метки: **[док]** — официальная документация, проверена лично по ссылке;
**[изм]** — опубликованный эксперимент с числами, **не перепроверялся**;
**[набл]** — наблюдение практика, не измерение.

---

# Главная поправка: короткий слой не покупает послушание

Я дважды говорил, что всегда-загружаемый слой разросся и его надо резать, ссылаясь
на документированную границу «до 200 строк на файл, иначе падает соблюдение» **[док]**.

**Измерения этого не подтверждают.** Факторное исследование на 1650 сессиях: размер файла
25 / 100 / 250 / 500 строк не дал заметного эффекта на соблюдение, байесовские факторы
0,05–0,10 — данные утвердительно говорят об отсутствии эффекта. Позиция инструкции
и даже намеренные противоречия между файлами — тоже без эффекта. Значимым оказалось одно:
**соблюдение падает примерно на 5,6% шансов с каждой дополнительной задачей внутри
сессии** **[изм]**.

Второй замер, про дистанцию: точное соблюдение правила — **13% без файла, 13% с разделом
в `CLAUDE.md`, 87% когда правило подаётся в момент действия** **[изм]**.

⚠️ **Оговорки, без которых эти числа врут.** Ни один из двух экспериментов не перепроверен
нами. У второго автор продаёт инструмент, который делает ровно то, что победило в замере,
и раскрывает это в самой статье. Первый целился в одну тривиальную аннотацию, а не в живой
свод правил.

**Что из этого берём как рабочую гипотезу:** резать слой стоит ради расхода токенов
(он копируется в каждый subagent), а не ради послушания. Послушание покупается
**переподачей правила рядом с действием** и **более короткими сессиями**.

# Иерархия для дочерних проектов — проверено лично

## Что наследуется, а что нет **[док]**

| | Вложенная папка | Отдельный репозиторий |
|---|---|---|
| `CLAUDE.md` | наследуется вверх по дереву | нет |
| **skills, agents, commands** | **только до корня репозитория** | нет |
| `settings.json` (общий) | **не наследуется** — читается из рабочей папки сессии | нет |
| `settings.local.json` | читается из корня репозитория | нет |

⚠️ **Поправка к отчёту агента.** Он писал, что `settings.json` наследуется вниз
по дереву и слои складываются. Проверено: Claude Code читает общий
`.claude/settings.json` **из рабочей папки сессии**, вверх по дереву не идёт.
Складываются слои «пользователь → проект → локальный → управляемый», а не каталоги.
Значит каждому этажу нужен свой файл прав.

**Ключевая деталь, подтверждённая в документации дословно:** проектные skills грузятся
из `.claude/skills/` в стартовой папке и в каждой родительской — **до корня репозитория**.

**Подмодуль сам себе корень.** Значит в `Site/` корневые skills не поднимутся,
хотя корневой `CLAUDE.md` туда дойдёт. Если отделы делать подмодулями, общие навыки
они потеряют.

Когда сессия стартует из подпапки — грузятся её файл и все родительские, сразу.
Когда из корня — только корневой, вложенные подтянутся, когда Claude тронет там файл.

**`CLAUDE.md` границу `.git` пересекает, навыки — нет.** Документация про память
дословно: грузится «из текущей рабочей папки и каждой папки выше», содержимое
выстраивается «от корня файловой системы вниз к рабочей папке». Про остановку
на репозитории не сказано ничего. Документация про навыки, наоборот, говорит прямо:
до корня репозитория. **Это и есть рычаг для вложенных подмодулей:** контекст течёт
сквозь них, навыки — нет, и общие навыки поэтому живут в `~/.claude/skills/`.

## Что переживает компакт **[док, проверено]**

| | После компакта |
|---|---|
| Системный промпт и стиль вывода | действуют |
| **Корневой `CLAUDE.md`** | **переинжектится с диска** |
| Авто-память | переинжектится с диска |
| Описания skills | пересобираются и подставляются заново |
| **Вложенный `CLAUDE.md`** | **перезагружается по требованию** — только когда Claude тронет там файл |
| Правила с `paths:` | по требованию |
| Прочитанные файлы | до пяти, самые свежие по дате изменения |
| Тела вызванных skills | 5 000 на skill, 25 000 суммарно, старые выбрасываются |
| Контекст, добавленный хуками раньше | суммаризуется вместе со всем |
| **`SessionStart` с матчером `compact`** | **запускается, вывод кладётся в сжатый контекст** |

Документация говорит прямо: если правило обязано пережить компакт, его место
в корневом `CLAUDE.md` — либо его возвращает хук. Третьего нет.

## Где именно дыра в документации

Про компакт документация говорит в двух местах, и оба описывают **ровно два случая**:

> Project-root CLAUDE.md survives compaction: after `/compact`, Claude re-reads it
> from disk and re-injects it into the session. **Nested CLAUDE.md files
> in subdirectories** and rules with `paths:` frontmatter load again on demand.
> — `code.claude.com/docs/en/memory`, раздел «Instructions seem lost after /compact»

Те же два случая в таблице выживания на странице `context-window`: корень проекта
и подпапки **ниже** рабочей.

**Про папки ВЫШЕ рабочей не сказано ничего, ни в одном из двух мест.** А для сессии,
запущенной в `marketing/site/`, генеральный `CLAUDE.md` лежит именно выше — он
не «корень проекта» и не «подпапка ниже». Он не попадает ни в один описанный случай.

Это не осторожная формулировка с моей стороны. Это **пробел в документации**:
поведение не описано, и обе трактовки правдоподобны.

**Поэтому на него не опираемся.** Строка про `SessionStart` с матчером `compact`
описана однозначно: Claude Code запускает хук и кладёт вывод в сжатый контекст.
Лифт делается хуком и работает независимо от трактовки.

**Как это померить, когда появится первый этаж:** в сессии этажа дождаться компакта
и запустить `/context` — он печатает список реально загруженных memory-файлов.
Тридцать секунд, и вопрос закрыт измерением, а не чтением.

## Правило выбора

**Вложенная папка** — когда дочернему нужны бизнес-решения родителя, а родителю
не нужен технический контекст дочернего. Это отделы: маркетинг, контент.

**Отдельный проект** — когда у дочернего свой длинный контекст, конкурирующий за то же
окно, свой remote и свой ритм. Это разработка: уже так и сделано.

**Передача — указателем, не копией.** `HANDOFF_dev.md` должен ссылаться на файл и раздел
в `docs/`, а не пересказывать их. Зафиксированные чужие грабли: решение скопировали
в оба места, копии разошлись, устаревшая пережила несколько ревизий **[набл]**.

# Subagents: сколько стоят и когда окупаются

- Subagent грузит при старте **всю иерархию `CLAUDE.md` плюс снимок git status** **[док]**.
  Полевой журнал на 858 запусках: медианные **~37 000 токенов накладных расходов
  на первом ходе**, до всякой работы **[набл]**
- Скорости не дают: одинаковая задача последовательно — 295k токенов за 4 мин 15 с,
  через пять subagents — 945k за 4 мин 45 с **[изм]**
- Именованные агенты впрок не окупаются: 9 из 17 заведённых не запустились ни разу,
  92% запусков были разовыми **[набл]**
- **На прозе агент-рецензент ненадёжен:** тот же проверяющий забраковал 29 из 46
  собственных находок на тексте и 0 из 70 на коде **[набл]**

**Вывод для нас.** Сеть именованных агентов заранее не строить. Окупается разовое
делегирование из разговора — исследование, которое иначе вывалит десятки килобайт
в основное окно. Ровно то, чем собран этот файл.

---

# Skills: поведение при компакте **[док, проверено]**

- При компакте **заново подставляется последний вызов каждого skill**, но не больше
  **5 000 токенов на skill** и **25 000 суммарно**. Заполняется от самого свежего,
  старые выбрасываются целиком
- Обрезка сохраняет **начало** файла — важное пишется вверху `SKILL.md`
- Пока skill не вызван, он стоит только имя и описание. При `disable-model-invocation: true`
  описание не грузится вообще — ноль до вызова `/имя`

**Срабатывание — реальный риск, а не цена.** Базовая полнота автоподхвата 46,3%,
после якорной фразы в описании — 67,3% **[изм]**. Вывод: то, что обязано сработать,
вызывается руками через `/имя`.

# Настройки, снимающие конфликт с правилами

В `CLAUDE.md` стоит «не ставить трейлеров и упоминаний агента в коммитах». Это
конкурирует со встроенной инструкцией Claude Code, которая велит обратное. Оба ключа
проверены в справочнике настроек **[док]**:

- `includeGitInstructions` — убирает встроенные инструкции про коммиты и PR из контекста
- `attribution` — объект с подключами `commit`, `pr`, `sessionUrl`.
  `includeCoAuthoredBy` устарел, заменён на него

⚠️ Агент предлагал `"attribution": ""` строкой — **это неверная форма**, ключ принимает
объект. Правильно:

```json
"includeGitInstructions": false,
"attribution": { "commit": "", "pr": "" }
```

Правило-просьба превращается в настройку-факт.

# Проверка, что документация не разошлась с реальностью **[док]**

Запускает Алекс из терминальной сессии, мне эти команды недоступны:

- **`/doctor prompt-audit`** — проходит по `CLAUDE.md`, rules, skills, commands,
  subagents; ищет ссылки на несуществующие файлы и команды, инструкции под старые модели,
  взаимно противоречащие файлы. Отчёт с предложениями, **ничего не меняет без просьбы**
- **`/context`** — живая разбивка расхода по категориям. Единственный способ узнать
  настоящую цену слоя: кириллица стоит заметно дороже посимвольно, ориентиры в строках
  нас недооценивают
- **`/doctor`** — отдельно предлагает обрезку закоммиченного `CLAUDE.md`

**Честный предел.** Противоречие внутри одного прозаического файла не ловит ничто.
При разборе 23 704 пунктов из 559 публичных файлов правил ~63% оказались вообще
не инструкциями, а из настоящих правил механически проверяемы ~43% **[изм]**.
Непроверяемый остаток — процесс, тон и суждение, то есть почти весь наш свод про тексты.

# Чего делать не надо

- **Не писать состояние в конце сессии.** Сессии обрываются по лимиту и по падению.
  Писать в момент решения. **У нас это правило уже есть** и подтверждается чужим опытом
- **Не наращивать хук `SessionStart` правилами в надежде на послушание.** Описанный отказ:
  инструкции были в контексте, но «сводка компакта создаёт нарративную инерцию, которая
  перебивает подставленные директивы» **[набл]**. Наш хук возвращает **факты** — так
  и оставить
- **Не использовать `@path`-импорты ради сокращения.** Импортированное грузится вместе
  с импортирующим, экономии ноль **[док]**
- **Не запускать `/init` на готовый `CLAUDE.md`** — он предложит переписать вручную
  настроенный файл. Для обрезки есть `/doctor`
- **Не заводить второй контекстный документ.** Чужие грабли подтверждают наше правило:
  отдельный `lessons-learned.md` разошёлся с индексом и был удалён; раздел «состояние
  проекта», дублировавший посекционные состояния, — тоже **[набл]**
- **Не строить векторное хранилище под память проекта** — файл можно прочитать, сравнить
  диффом и проверить следующим агентом, хранилище только запросить **[набл]**
- **Не хранить полные транскрипты сессий** — их никто не читает. Короткая запись решения
  и тупика читается. Наш `progress.md` именно такой

# Про наше правило «контекстный документ ровно один»

Я раньше отмечал, что оно противоречит реальности: есть `ROADMAP.md`, `QUESTIONS.md`
и `docs/`. **Противоречия нет.** Правило о документах вида «почему так вышло» —
решения с причинами, отклонённое, разборы. Таким остаётся один `CONTEXT.md`.
Остальные — не контекстные: этапы, открытые вопросы, закрытые темы по одной на файл.
Правило менять не нужно, достаточно формулировки, что именно считается контекстным.
